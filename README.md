# Бот-консультант Никиты Толмачёва

Telegram-бот на aiogram 3: приветствие → каталог из 6 категорий товаров →
карточка товара → кнопка **«Написать мне для оплаты»**, которая открывает
личный чат с тренером в Telegram с уже готовым сообщением.

## Структура проекта

```
tolmachev_bot/
├── bot.py                    # точка входа, регистрация роутеров и middleware
├── config.py                  # чтение .env
├── requirements.txt
├── .env.example
├── Dockerfile
├── users.json                   # создаётся автоматически — база id для рассылки
├── data/
│   ├── products.py                # все товары: цена, описание, фото
│   ├── texts.py                     # все тексты бота
│   └── storage.py                     # хранилище id пользователей (для рассылки)
├── handlers/
│   ├── start.py                    # /start, /menu, /whoami, "В начало"
│   ├── catalog.py                    # категории → карточка товара
│   ├── broadcast.py                    # /broadcast — рассылка по всем пользователям
│   └── common.py                         # fallback на непредусмотренный ввод
├── middlewares/
│   └── track_user.py                # сохраняет id каждого написавшего боту
└── keyboards/
    ├── main.py
    ├── catalog.py
    └── product.py
```

## Как теперь устроена оплата

Никаких реквизитов и подтверждения оплаты внутри бота больше нет — это
убрано как рисковое. Вместо этого:

1. Клиент открывает карточку товара.
2. Жмёт **«✍️ Написать мне для оплаты»**.
3. Открывается личный чат с тренером (`@Tolmachev92`) с уже вписанным
   сообщением вида:

   ```
   Привет Никита, хочу обсудить 4-дневный сплит под DDX
   ```

4. Дальше всё общение, оплата и её подтверждение идут напрямую в личке —
   бот в этом не участвует.

Ссылка собирается автоматически в `keyboards/product.py` из
`TRAINER_USERNAME` (`.env`) и названия товара — руками ничего заполнять не
нужно.

## Рассылка по пользователям (`/broadcast`)

Бот запоминает `chat_id` каждого, кто хоть раз ему написал (`middlewares/track_user.py`
сохраняет id в `users.json` через `data/storage.py`).

Как разослать сообщение всем:

1. Тренер (чей `chat_id` указан в `.env` → `TRAINER_CHAT_ID`) пишет боту `/broadcast`.
2. Бот просит прислать сообщение — подойдёт текст, фото, видео, документ и т.п.
3. Тренер присылает это сообщение.
4. Бот копирует его каждому пользователю из базы (с небольшой паузой между
   отправками, чтобы не упереться в лимиты Telegram) и присылает тренеру
   итог: сколько доставлено и сколько нет.

Отменить рассылку на шаге «пришли сообщение» — командой `/cancel`.
У всех, кроме тренера, команда `/broadcast` просто не срабатывает.

## Как узнать TRAINER_CHAT_ID

Telegram Bot API не умеет слать сообщения "по юзернейму" — только по
числовому `chat_id`. Поэтому:

1. Тренер (`@Tolmachev92`) открывает бота и пишет `/whoami`.
2. Бот присылает его `chat_id`.
3. Впишите это число в `.env` → `TRAINER_CHAT_ID`.

Без этого шага команда `/broadcast` будет недоступна.

## Запуск

```bash
cp .env.example .env
# впишите BOT_TOKEN, TRAINER_USERNAME и TRAINER_CHAT_ID

python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

python bot.py
```

## Запуск в Docker

```bash
docker build -t tolmachev-bot .
docker run -d --restart unless-stopped --env-file .env --name tolmachev-bot tolmachev-bot
```

Обратите внимание: `users.json` для рассылки создаётся внутри контейнера —
если контейнер пересоздаётся с нуля, стоит примонтировать volume под него
(`-v $(pwd)/users.json:/app/users.json`), иначе база пользователей будет
теряться при пересборке образа.

## Креативы (фото-карточки товаров)

У каждого из 15 товаров есть свой креатив — `PRODUCTS[key]["photo"]` в
`data/products.py` хранит Telegram `file_id` картинки. Когда пользователь
открывает товар, бот присылает не голый текст, а фото с подписью и
кнопками под ним (`handlers/catalog.py`, `show_product`).

**Важно:** `file_id` жёстко привязан к конкретному боту, который первым
принял это фото. Если вы смените `BOT_TOKEN` на токен другого бота — все
15 `file_id` перестанут работать, и бот на этот случай тихо откатится на
текстовую карточку без фото (см. `try/except TelegramBadRequest` в
`show_product`).

То же самое касается фото в приветственном сообщении (`/start`) —
`WELCOME_PHOTO_ID` в `.env` / `config.py`, с тем же тихим откатом на текст
без фото при смене бота (см. `handlers/start.py`, `send_welcome`).

## Продакшен-заметки

- `MemoryStorage` для FSM — состояния (в т.ч. состояние `/broadcast`)
  сбрасываются при перезапуске бота.
- `handlers/common.py` подключён последним и ловит любые необработанные
  сообщения и нажатия на устаревшие кнопки — бот никогда не "зависает"
  молча и не оставляет "часики" на кнопке.
- `bot.delete_webhook(drop_pending_updates=True)` перед polling — на
  случай, если ранее был включён webhook или накопились старые апдейты.
- Кнопка «Написать мне для оплаты» — обычная url-кнопка на `https://t.me/...`,
  без callback-данных, поэтому Telegram открывает личку клиента с тренером
  напрямую, минуя бота.
